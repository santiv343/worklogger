# Daily overview with Worklogger

Build the view from read-only Worklogger tools: own hours for the current week,
assigned sprint issues without own worklogs, and optional scoped Bitbucket pull
requests. Keep Jira hours distinct from repository activity and meetings.

State whether data is complete, limited, unavailable or disabled. Reuse the
issue and repository context found here when the user continues into a Jira or
delivery action; do not ask them to repeat it. A later write still requires its
own visible preview and explicit confirmation.
